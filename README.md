# Biblia sin prisas

Бесплатный лектор для чтения Библии и сравнения переводов. Язык меню выбирается отдельно от языка текста. Посетителям достаточно открыть сайт: настройки и последнее место чтения запоминаются в их браузере.

## Как посмотреть проект у себя

1. Установите [Node.js 24 LTS](https://nodejs.org/).
2. Скачайте или клонируйте эту ветку GitHub. Откройте папку проекта в терминале.
3. Выполните `npm ci`, затем `npm run dev`.
4. Откройте адрес, который появится в терминале. Обычно это `http://localhost:5173/`.
5. Для проверки проекта разработчиком доступны `npm test` и `npm run build`.

Для чтения и проверки ссылок «Поделиться» можно запускать проект сразу. При открытии ссылки полезно попробовать другой браузер или окно инкогнито. Ссылка восстанавливает книгу, главу, первый стих, число стихов, число колонок и редакции переводов. Язык меню и размер текста остаются личными настройками читателя.

## Как подключить свой канал и каталог видео

Для подключения канала создайте копию файла `.env.example` с именем `.env.local` и укажите полный адрес вашего канала в строке `VITE_YOUTUBE_CHANNEL_URL`. При желании заполните `VITE_CONTACT_EMAIL` публичным адресом для обращений. После изменения перезапустите локальный сайт. В опубликованной версии те же поля задаются в настройках сборки, после чего нужна новая сборка.

Один раз настройте хранение видео в [Supabase](https://supabase.com/). Стартового бесплатного проекта достаточно для первой версии в рамках лимитов сервиса.

1. В панели Supabase создайте проект и откройте **Authentication → Users**. Создайте один аккаунт владельца с подтверждённым адресом электронной почты и скопируйте его **User UID**. Используйте уникальный пароль.
2. В настройках **Authentication** отключите возможность новых регистраций (**Allow new users to sign up**). Читателям аккаунт не нужен.
3. Откройте **SQL Editor → New query**. Вставьте содержимое [supabase/setup.sql](supabase/setup.sql). Замените в запросе `00000000-0000-0000-0000-000000000000` на свой **User UID**, сохраняя кавычки. Нажмите **Run**.
4. В Supabase откройте **Connect** или **Settings → API Keys**. Скопируйте адрес проекта и ключ **Publishable**. В `.env.local` заполните `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`. Поля с префиксом `VITE_` доступны браузеру. Пароль владельца и ключи **Secret** / **service_role** храните отдельно.
5. Перезапустите сайт и добавьте `/admin` к его адресу. Войдите с почтой и паролем владельца.
6. Нажмите «Добавить видео». Укажите базовое название, ссылку на конкретный ролик и диапазон стихов внутри одной главы. Переводы названия можно заполнить для каждого языка. Если отдельного названия для языка читателя нет, отобразится базовое.
7. Нажмите «Сохранить». Откройте лектор и выберите первый стих из указанного диапазона. При изменении ролика новая версия записи появится в лекторе автоматически. Повторная сборка сайта для смены записей не нужна.

В разделе `/admin` рядом с записью есть действия «Изменить» и «Удалить». В совпадающих диапазонах приоритет получает более узкий. Если с первым стихом ролик не связан, для последующих стихов появятся компактные ссылки. Для роли читателя база разрешает только чтение. Проверка владельца при добавлении, изменении и удалении выполняется в самой базе.

## Развёртывание на Cloudflare Pages после согласования

В Cloudflare Pages подключите GitHub-репозиторий и выберите согласованную ветку. Команда сборки — `npm run build`, папка результатов — `dist`, версия Node.js — 24 (при необходимости задайте `NODE_VERSION=24`). Здесь же укажите публичные параметры из `.env.example` в настройках production и preview, если нужны обе среды. Сайт — одностраничное приложение, поэтому Cloudflare Pages обслуживает адрес `/admin` через стандартный возврат к `index.html`. Настройте домен в панели Pages после проверки. Развёртывание в рамках этой работы не выполнялось.

## Тексты и условия распространения

В библиотеку входят 66 книг для девяти конкретных цифровых изданий. Карточки в разделе «Переводы» и файл [с атрибуцией](public/scripture/attribution/README.txt) содержат имена источников, даты, сведения о правах и ссылки. В исходных текстах стихи сохранены в редакции поставщика. При импорте убраны редакционное оформление, заметки и заголовки вне стихов. Иллюстрации, карты и оформление печатных изданий не включены.

У конкретного выпуска GetBible иные условия распространения. Поэтому для сравнения пока используется Bible David Martin 1744. Для португальского добавлен лицензированный выпуск Bíblia Livre, а историческая Almeida остаётся кандидатом на импорт после проверки полного цифрового текста и его лицензии. [Уведомление Cambridge о правах на Authorized Version](https://assets.cambridge.org/97805212/28626/copyright/9780521228626_copyright_info.pdf)

## Как сопоставляются стихи и добавляются новые переводы

Навигация и диапазоны видео следуют нумерации архивной World English Bible. Дополнительные редакции хранят исходные номера. Для однозначных смещений используется явная карта соответствий, например WEB Бытие 31:55 соответствует Lutherbibel 32:1. У некоторых редакций стихи объединены, разделены или переставлены. При спорной нумерации лектор показывает предупреждение и даёт открыть текст главы в нумерации цифрового источника. Покрытие карт различается по изданиям.

Чтобы добавить новый перевод, подготовьте JSON с данными редакции и стихами. Проверьте право на распространение именно этого файла. Пример формы импорта ниже содержит пустые места для реальных данных, а не библейский текст.

```json
{
  "edition": {
    "id": "edition-id",
    "lang": "fr",
    "name": "Название издания",
    "year": "Год",
    "publisher": "Издатель или правообладатель",
    "license": "Лицензия",
    "rights": "https://example.org/rights",
    "source": "https://example.org/digital-source",
    "website": "https://example.org/publisher"
  },
  "books": {
    "GEN": {
      "native": {},
      "aligned": {}
    }
  }
}
```

Заполните `native` по схеме «глава → номер стиха → текст». В `aligned` с каждым номером главы WEB свяжите явные пары «номер стиха WEB → [глава издания, номер стиха издания]». Значение `"same"` указывайте только после подтверждения, что в этой главе системы совместимы. При неизвестном соответствии оставьте поле главы пустым. Выполните `node scripts/add-edition.mjs path/to/edition.json`. После добавления записи примените к новым статическим файлам условия лицензии издания. У редакции может быть необязательная ссылка `purchase` на покупку.

Для воспроизводимой сборки начального набора используйте `python3 scripts/import-translations.py <папка>`. Скрипт заново формирует начальный набор и рассчитан на отдельную чистую ветку. Скачайте из источников в `src/catalog.json` файлы `spa-rv1909.usfx.xml`, `spa-bes.usfx.xml`, `spa-vbl.usfx.xml`, `eng-web.usfx.xml`, `eng-bsb.usfx.xml`, `deu-luther1912.osis.xml` и `bliv-n4_vpl.txt` (из архива `bliv-n4_vpl.zip`). Два текста из GetBible сохраните как `martin.txt` и `synodal.txt`. Таблицы соответствий поставляются в `public/scripture/attribution/crosswire/`. Переключатель переводов читает общий каталог и работает с новым изданием без изменений в React.

## Структура проекта

- `src/` — лектор, шесть языков интерфейса, список изданий и раздел владельца.
- `public/scripture/` — тексты и соответствия стихов по книгам.
- `supabase/` — разовая настройка хранения видео и прав владельца.
- `scripts/` — подготовка цифровой библиотеки.
- `tests/` — проверки навигации, переводов, хранения настроек, ссылок и видео.
